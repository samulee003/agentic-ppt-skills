# STORY

**Outcome:** Developers leave knowing how an agent structures its loop (read, plan, write, verify) and how to match human review to each action's risk.

## Arc

The talk moves the audience from **"what is the loop"** to **"where does feedback enter"** to **"how do we read the one number"** to **"where are the boundaries."** Each chapter is one necessary job; the benchmark slide is deliberately placed after the loop/tools chapters so the audience has the mental model to interpret it correctly — never as an opening hook.

## Chapters

1. **Welcome** — name the thing. One sentence framing, no claims yet.
2. **The loop** — read, plan, write, verify. The core mental model. No numbers.
3. **The tools** — how the model reaches the world. Names are illustrative; the contract is the point.
4. **The one benchmark** — 1.96%, historical, heavily caveated. The deck's only numerical claim; everything around it is qualitative.
5. **The boundary** — review matches risk. The closing principle.

## Why this order

The benchmark is dangerous out of context (it reads as a performance promise). Putting it fourth, after the loop and tools, gives the audience the frame to hear it as a historical baseline. The safety chapter closes so the audience leaves thinking about boundaries, not capability.
